# SkyRescue 双模型人工指令复现实验结果（v1.1.0）

## 复检与实验设置

本轮首先重新读取 `key.md`，分别向 DeepSeek 和阿里千问发送一条健康检查请求。两个 API 均连接成功，服务端返回的实际模型标识分别为 `deepseek-v4-flash` 和 `qwen3-30b-a3b-instruct-2507`；两条响应均成功解析为 JSON 并通过 Schema 校验。

随后沿用第一轮完全相同的 100 条专家金标准指令、固定系统提示词和三阶段处理流程。参数继续固定为 `temperature=0`、`top_p=1`、`max_tokens=512`，每条指令运行一次；DeepSeek 的 `thinking` 显式设为 `disabled`。每个模型的同一份原始响应依次用于直接 JSON、Schema 校验和完整 SkyRescue 编译，未在不同阶段重新采样。

本目录名中的 `replication_v1.1.0` 表示第二轮独立运行；`manifest.json` 中的 `SkyRescue-HumanIntent-LLM-v1.0.0` 表示保持不变的实验协议版本。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepSeek-V4-Flash | 100.00% | 100.00% | 94.00% | 65.86% | 2.00% | 64.00% | 1372.4 |
| Qwen3-30B-A3B-Instruct-2507 | 100.00% | 100.00% | 100.00% | 62.14% | 0.00% | 76.00% | 930.5 |

以每条指令的 7 个字段正确数进行配对比较，DeepSeek 在 41 条上更高，千问在 23 条上更高，36 条并列；双侧精确符号检验 `p=0.0328`。第二轮再次表明，DeepSeek 的总体字段抽取准确率较高，而千问在 Schema 合规率、编译结果准确率和响应延迟上更优。

## 两轮结果稳定性

| 模型 | 字段准确率：第一轮→第二轮 | Schema：第一轮→第二轮 | 编译结果：第一轮→第二轮 | 两轮字段预测一致率 | 两轮整条预测一致率 | 两轮编译结果一致率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepSeek | 66.43%→65.86% | 95%→94% | 67%→64% | 96.43% | 79.00% | 95.00% |
| 千问 | 62.57%→62.14% | 99%→100% | 76%→76% | 92.00% | 60.00% | 90.00% |

两轮 API 成功率和直接 JSON 解析率均为 100%。DeepSeek 和千问的字段微准确率分别只变化 0.57 和 0.43 个百分点，主要结论保持一致。尽管设置 `temperature=0`，两个在线推理服务仍未实现逐条输出完全确定；因此论文应将 `temperature=0` 表述为低随机性固定设置，不应写成“完全确定性生成”。

DeepSeek 的两轮字段预测一致率为 96.43%，高于千问的 92.00%；千问的编译结果准确率两轮均为 76%，但逐条编译结果一致率为 90%，说明总体指标稳定并不意味着每条样本的决策完全相同。

## 建议写入论文的结论边界

两轮实验支持以下结论：两个国内模型均能稳定产生机器可解析候选任务；DeepSeek 在总体字段抽取上更优，千问在 Schema 合规和编译结果判断上更优；完整编译层能够将语言模型候选任务转化为可执行工作流或结构化拒绝结果；两轮复现保持了相同的模型排序和主要误差模式。

本实验不能证明真实飞行安全、开放攻击防御或跨地区语言表达的全面泛化。论文中应将其表述为“人工指令金标准上的真实 API 候选任务生成实验”，并与合成规模实验、故障检测实验分别报告。
